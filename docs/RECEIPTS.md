# Чеки (PDF / Email / публичная ссылка)

## Что это

Система формирует пользовательские чеки для операций (пополнение/покупка):
* хранит реквизиты продавца/покупателя и состав позиции;
* генерирует PDF;
* отправляет PDF на email;
* предоставляет скачивание из кабинета и по публичной ссылке;
* добавляет QR‑код для проверки подлинности.

## Где видно пользователю

* Кабинет: `/receipts` (список)
* Кабинет: `/receipts/{receipt}` (детали)
* Скачать PDF: `/receipts/{receipt}/download`

## Публичные ссылки

* Открыть: `/r/{receipt}/{token}`
* Скачать: `/r/{receipt}/{token}/download`
* Проверка: `/r/{receipt}/{token}/verify`

QR‑код внутри PDF ведёт на страницу проверки.

## Защита от подделки

Подлинность подтверждается через подпись `HMAC-SHA256` от ключевых полей чека.
* подпись хранится в `receipts.signature`;
* `token` — отдельный публичный токен доступа;
* проверка выполняется на маршруте `/verify`.

## Переменные окружения (реквизиты продавца)

* `ORG_NAME`
* `ORG_SITE`
* `ORG_INN`
* `ORG_KPP`
* `ORG_ADDRESS`
* `ORG_PHONE`
* `ORG_EMAIL`

Если реквизиты не заполнены, чек всё равно сформируется, но поля будут пустыми.
