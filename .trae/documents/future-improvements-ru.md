# Что ещё можно улучшить (предложения)

Ниже — список улучшений, которые дадут максимальный эффект по стабильности, безопасности, UX и росту органики. Это не «обязательные правки», а дорожная карта.

## 1) UX и интерфейс
- Добавить глобальные toast-уведомления (success/error/info) во всех layout’ах и единый стиль алертов.
- Сделать единый UI-kit (кнопки, инпуты, модалки, таблицы) и убрать разрозненные классы Tailwind в шаблонах.
- Добавить пустые состояния и подсказки на ключевых страницах: биллинг, инфраструктура, тикеты.
- Улучшить «Финансы»: показать статусы платежей (ожидает/успешно/ошибка), историю попыток и ссылку на чек (если доступно).

## 2) Платежи и надежность
- Добавить страницу «История платежей» (список Payment) и деталку платежа с таймлайном webhook-событий.
- Реализовать ручную кнопку «Проверить статус платежа» (GetState) и механизм reconciliation.
- Вынести бизнес-логику платежей в сервис/команду, добавить отдельные доменные статусы (pending/confirmed/rejected/refunded).
- Добавить идемпотентность на стороне Init (например, по user+amount+окно времени) чтобы исключить двойные платежи при повторной отправке формы.

## 3) Безопасность
- Добавить rate-limit на чувствительные эндпоинты (login, forgot-password, payments/create, telegram/webhook).
- Добавить CSRF/Origin проверки для критичных UI-форм и строгий Content Security Policy (CSP) для публичных страниц.
- Добавить журнал «админ-действий» (отдельная витрина в админке) с экспортом и фильтрами.
- Добавить автоматические проверки секретов: запрет на логирование токенов, маскирование ключей в конфиг‑выводах.

## 4) Логи и наблюдаемость
- Добавить страницу «Системные события» (очереди, webhooks, pterodactyl) доступную только админам.
- Добавить метрики: количество ошибок webhook/notify за 24ч, среднее время обработки очереди, число ретраев.
- Свести `UserLog` и `AuditLog` к одной системе (оставить AuditLog как источник правды), чтобы не дублировать данные.

## 5) SEO и контент
- Добавить human-readable заголовки/описания для всех публичных страниц (контакты/блог/база знаний/документы).
- Развернуть блог/knowledge base как отдельную сущность (категории, статьи, ЧПУ, превью, теги).
- Добавить `hreflang` (если планируется мультиязычность) и `breadcrumbs` (Schema.org).
- Подключить верификацию домена: `yandex-verification`, `google-site-verification` через env.

## 6) Производительность
- Добавить кеширование витрины (категории/услуги/прайс) на 1–5 минут.
- Оптимизировать N+1 запросы на страницах: инфраструктура/заказы/платежи.
- Включить HTTP caching для `sitemap.xml` и `robots.txt`.

## 7) Pterodactyl
- Добавить страницу для пользователя: «Состояние сервера» (без тех. параметров), отдельную — для админа с деталями.
- Добавить механизм «повторить провижининг» и «пере-синхронизацию» с понятными причинами ошибок.
- Добавить таблицу `sync_runs` (история синков) с корреляцией по заказу/серверу.

## 8) Email/Telegram
- Добавить управление предпочтениями уведомлений по типам событий (вход/платеж/тикеты/заказы), а не только по каналам.
- Добавить шаблоны email (брендированная верстка) и унифицированные шаблоны Telegram сообщений.
- Добавить антиспам-защиту от “шумных” событий (дедупликация уведомлений за короткий период).

## 9) Тестирование и CI
- Добавить feature-тесты для: payments/create (ошибка конфигурации, валидация суммы), отображение flash-ошибок, SEO endpoints.
- Добавить CI (GitHub Actions): запуск `php -l`, `vendor/bin/pint --test`, `php artisan test`.
